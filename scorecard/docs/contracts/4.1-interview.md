# §4.1 Interview answers and handoff

## Files

| Path | Type | Writer |
|------|------|--------|
| `content/interview.json` | `InterviewFile` | Interview form (WS2), Write mode |
| `content/interview-handoff.json` | `InterviewHandoffFile` | Form “Done” export (WS2), optional |

## Trust model

- Form binds **127.0.0.1** only; no session tokens.
- Agents treat answers as **hints** — infer-first, redact secrets.
- Only form-submitted keys may use `provenance: "confirmed"`; agents never auto-confirm generated content.

## `InterviewFile`

See fixture `fixtures/interview.sample.json`.

- `submittedAt` — ISO-8601 when the form was last submitted.
- `profile.projectName` — required before site generation (pairs with §4.2).
- `answers` — map of question keys to `{ value, provenance, evidence? }`. Legacy bare values are accepted until normalized.
- `narrative` — optional `hook`, `proudMoment`.
- `agentNotes` — omitted from public UI; included in handoff when set.

## Handoff

`buildInterviewHandoff()` in `schemas.ts` produces `InterviewHandoffFile`: profile, non-empty answers, narrative, and `agentNotes`. Empty skips are dropped.

## Validation

- `validateInterview(file, { requireProjectName?: boolean })`
- `validateInterviewHandoff(file)`
- `interviewNeedsForm(file)` — WS2 CLI uses this to open `/interview` when answers are empty.
